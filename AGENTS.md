# AGENTS.md

Guide for AI agents and contributors working on **PunkWeb** — a punk-styled, scroll-driven site built with Vite + React 19 + TypeScript.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server (http://localhost:5173) |
| `npm run build` | Type-check (`tsc -b`) and production build to `dist/` |
| `npm run lint` | Lint with oxlint — keep it at zero warnings |
| `npm run preview` | Serve the production build |
| `npm run frames` | Re-extract video1 frames to `public/frames/video1/` (macOS only, uses AVFoundation via `scripts/extract-frames.swift`) |

Run `npm run build && npm run lint` before finishing any change.

## The intro sequence

Phases (`src/features/intro/types.ts`), in order:

1. **loading** — preload all video1 frames; scroll locked; `Loader` shows %.
2. **scrub** — scroll position scrubs video1 frames on a canvas; near the end a black gradient sweeps in from the right (scroll-controlled, reversible), then a solid black hold. Captions follow scroll.
3. **reveal** — at the end of the black hold the scroll locks and the darkness recedes to the right over video2's first frame (timed, `revealMs`).
4. **playing** — video2 plays muted (scroll locked; safety timeout prevents getting stuck). The smoke starts `smokeLeadMs` before video2 ends, and video2 keeps playing underneath it.
5. **smoke** — white smoke from the top-left fills the screen in `smokeMs` (scroll locked).
6. **done** — stage stays white with the white-screen caption(s), scroll unlocks, content below (`sections/`) follows.
7. **rewind** — scrolling back up from white (from the stage or the content below) jumps to `scroll.rewindTo` (near the end of video1) under the white, then the smoke plays in reverse (`rewindMs`, scroll locked) and the phase returns to **scrub**. The whole sequence can be replayed.

Scroll is only ever locked in `SCROLL_LOCKED_PHASES` (loading, reveal, playing, smoke, rewind). When moving into a locked phase, call `window.scrollTo` **before** `setPhase` — `useScrollLock` pins whatever position it sees when it engages.

### Captions

- Copy lives in `src/content/messages.ts`. Never hard-code phrases in components or config — pick them with `getLines(sceneId, start, end)` (slice semantics).
- `introConfig.captions.scroll` is a list of cues `{ lines, from, to, anchor? }` (screens); `anchor` overrides the golden-ratio placement (the black-screen cue is centred and derived from `DARKNESS_END`/`BLACK_END` in `config/intro.ts`, so it only appears once the screen is fully black); each cue's lines split its range evenly (`sampleCaption` in `lib/timeline.ts`). `captions.white` holds the time-driven lines for the white screen, centred via its own `anchor`.
- **Reading holds:** a cue's `holdLines` marks phrases that must not be skipped. When scrolling crosses into one (even in one big jump), the page snaps onto it and scroll locks for `captions.readHoldMs`; the hold re-arms once the user scrolls back above it. Currently used for "sit down, shut up, fit in." right before the locked video2. `useScrollLock(locked, pinY)` takes an explicit pin position for this.
- `GlitchCaption` shows one phrase at a time, glitching out the old phrase and in the new one. Lines starting with `!` are hits: the `!` is stripped and they get a larger "stamp" animation. Its handle's `show(line, { tone, anchor })` is safe to call every frame; `anchor` defaults to the golden-ratio `captions.anchor`.
- `tone: 'light'` (over video/black) adds a soft dark scrim behind the text for legibility; `tone: 'dark'` (on white) has none.

Scroll distances in `config/intro.ts` are in **screens** (1 = one viewport height). The track height is derived from them in `getTimelineLayout`, so changing a number there is all that's needed.

## Conventions

- **No per-frame React renders.** Scroll/animation updates go through imperative handles (`FrameScrubberHandle.update`, `DarkOverlayHandle.setCoverage`) driven by a single rAF loop. React state is only for phase changes.
- **Pure logic lives in `lib/`** (no React, no DOM where possible) so it's testable and reusable. Components stay thin.
- **Config over constants.** New timings/asset paths go in `src/config/`.
- **Features are folders.** New big pieces go under `src/features/<name>/` with an `index.ts` barrel; simple page blocks go in `src/sections/`.
- **Styling:** CSS Modules (`*.module.css`) per component; shared tokens as CSS custom properties in `styles/global.css`. Use `svh` for full-height layouts.
- **React 19:** pass `ref` as a normal prop (no `forwardRef`).
- **Videos are always `muted playsInline`.** The only sound is the background music (`features/audio`).
- **Audio autoplay rules:** browsers block sound until a click/tap/key — scrolling (wheel/trackpad) does not count. `useBackgroundMusic` tries immediately, retries on every gesture, and the `SoundToggle` gives visitors an explicit control; a visitor's "off" is remembered in localStorage. Music fades out and suspends while the tab is hidden.
- Music plays through the Web Audio API (`lib/loopPlayer.ts`) because `<audio loop>` leaves an audible gap at the loop point with AAC files.
- Respect `prefers-reduced-motion` (`useReducedMotion`) for new effects.
- Never leave the user scroll-locked without an exit path (timeouts/error handlers). Every timed transition that gates a locked phase needs a safety timer (see `SmokeTransition`).
- **Clamp time-based progress:** `clamp((now - start) / duration)`. rAF timestamps can be *earlier* than a `performance.now()` taken just before, so unclamped progress can go negative — that once produced `NaN` in the smoke maths, threw inside the rAF loop and stranded users on the locked smoke phase.
- Preloading must not wait on `img.decode()` (it can stay pending in background tabs); wait for `load`/`error` and treat decode as a warm-up.

## Media notes

- video1 is shown as an image sequence, not a `<video>`: scrubbing `currentTime` on H.264 is jerky. If you replace video1, run `npm run frames` and update `introConfig.video1.frameCount`.
- Frames are JPEG q≈0.6 (~14 MB total). If load time matters, consider converting to WebP/AVIF or lowering resolution on mobile.
- The `resources/Transition/*.jpg` stills are the visual reference for each transition — check them before changing an effect.
